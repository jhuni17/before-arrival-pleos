출처 필터 보존 검증 자료

source-report.json은 기준 HEAD(candidateSha), 미커밋 변경 여부(workingTreeDirty), 소스·검사 파일·생성 HTML·주야간 320/390 캡처 12개의 SHA-256을 기록한다. 새 후보 커밋은 만들지 않았다. 이 보고서는 기록된 소스 해시의 작업 트리를 검증한다.

출처 선택은 before-arrival-saved-source-v1에 JSON 문자열로 저장한다. 전체 출처와 ‘조건 모두 지우기’도 보존하며 제목 검색은 재로드하면 비운다. 등록 출처가 삭제되어도 정식 출처 ID와 공식 URL 검증을 통과한 저장 항목을 유지한다. 등록 목록·저장 항목 모두에 없는 출처와 잘못된 값·읽기 실패는 전체 출처로 돌아가 이유를 표시한다. 저장 실패는 현재 화면에만 적용되었다고 안내하며 명시적 재시도를 제공한다. 복원 과정에서 저장 항목이나 위치 키를 다시 쓰지 않는다.

고정 32건으로 출처·미확인 교집합, 재방문, 등록 출처 삭제, 없는 출처, 잘못된 JSON/타입, 읽기 거부, 쓰기 실패와 재시도, 초기화를 검사한다. 저장 객체 전체와 위치 키를 비교하고 필터가 숨긴 위치의 이동 비활성화·이유를 확인한다. restricted/unknown 및 주차 복귀 후 오래된 출처 핸들러가 변경·저장을 하지 않으며 재생·원문 열기가 발생하지 않는지 검사한다. 기존 출처·제목·미확인 조합, 삭제/확인 실행 취소, 다음 미확인 이동 회귀도 유지한다.

주야간 320×960·390×1080에서 32건 목록의 첫 제목 노출, 키보드 선택·Enter/Space 초기화와 이동, 검색 초점, 대비·글자 크기·가로 넘침을 검사한다. 기존 CI 필수 명령 verify:saved-undo가 saved-source-browser-verify.mjs를 호출하므로 CI 설정 변경 없이 연결된다. 캡처는 Asta Sans/OFL을 포함한 생성 HTML을 사용한다. 기존 일부 버튼의 한글 네모 렌더링과 물리적 한국어 IME는 별도 수동 확인 대상이다.

샘플 경로·재생 연출이며 저장은 현재 브라우저 주소에만 남고 Android 앱/다른 기기와 동기화하지 않는다. 이번 변경은 Android 소스를 수정하지 않았다. 브라우저 검사는 APK 빌드·설치·에뮬레이터·실제 Pleos SDK 콜백·제출 준비 완료의 근거가 아니다.

실행 결과: build, verify(삭제된 등록 출처 복원·비공식 URL 거부 추가), verify:server(30건), 최종 saved-source-browser-verify, 최종 saved-position-browser-verify, git diff --check 통과. source-report.json의 기준 SHA·소스 7개·HTML·캡처 12개 해시를 파일과 재대조했다. 첫 제목 검사는 긴 출처명·저장 위치가 있는 32건 목록에서도 통과했다. 반복 출처명은 한 줄 말줄임이며 선택기·툴팁에서 전체 이름을 확인한다.

verify:arrival과 저장 삭제 실행 취소 검사는 통과했다. review-undo-browser-verify 단독 재실행도 통과했다(마지막 출처명 말줄임 표시 수정 이전 HTML). 최종 출처 검사에서도 삭제/확인 실행 취소와 모바일 제목·초점 회귀를 확인했다. verify:saved-undo 전체 묶음과 verify:browser는 완료 전 종료 코드 143으로 중단되어 전체 회귀 통과로 간주하지 않는다. Android 검사는 실행하지 않았다. 이전 시도의 잘못된 테스트 URL, 필터 초기화 가정, 첫 제목 노출 실패를 수정한 뒤 위 최종 출처·위치 검사를 통과했다. 기존 .txt/.log는 이전 작업 기록이며 이번 근거는 source-report.json과 이 실행 기록이다.

최종 saved-item-next-browser-verify 단독 검사도 통과했다. 위치·항목별 이동 검사에서 전체 목록을 준비할 때는 보존된 출처 선택을 명시적으로 전체 출처로 바꾸며, 실제 제품의 보존 동작을 초기화된 것으로 가정하지 않는다. 최종 git status(미추적 포함)의 모든 변경은 README.md 또는 showcase/ 안에 있고, 보고서·캡처는 showcase/validation/ 안에 있다. 커밋·푸시·CI 변경·서명 키 생성·라이선스 수락·SDK 자격 증명 변경은 하지 않았다.
