# 도착 전에 시연 검증 기록

Stageshow의 `device-pair`를 시작점으로 차량 콘솔과 휴대폰 보관함을 배치했다. `Stage`, `Phone`, `Count`로 화면 구성과 상태 전환을 구현했다.

1. 도착까지 18분인 주차 상태에서 설정한 게임 패치를 먼저 보여준다.
2. 차량에서 게임 패치를 저장하면 휴대폰 보관함에 패치가 나타난다.
3. 도착까지 4분으로 바뀌면 회의 장소 변경을 먼저 보여주고 게임 패치와 커뮤니티는 나중으로 미룬다.
4. 회의 안내와 휴대폰 보관함을 마지막 프레임에 남긴다. 다시 보기로 처음부터 재생할 수 있다.

단일 HTML에 CSS와 스크립트를 포함했다. 원본은 1,080px 스테이지와 358px의 좁은 배치로 나뉜다. 축소 모션 환경에서는 최종 상태를 표시한다. 시연에는 예시 데이터가 들어가며 휴대폰 저장은 화면 연출이다.

## 확인한 항목

esbuild 번들을 만들고 Node에서 실제 React 컴포넌트의 초기, 우선순위 전환, 저장 완료 상태를 렌더링했다. 단계별 리드 카드와 숫자, 보관함 상태, 동기화 안내 문구 및 동작 호출 순서를 검사했다.

## 확인 범위

브라우저에서 1,080px와 390px의 픽셀, 모션 및 축소 모션을 확인하는 리허설은 보류했다. 헤드리스 브라우저의 파일 캡처가 정상 이미지로 저장되지 않았고 Work의 로컬 브라우저 도구는 비활성화되어 있었다. 따라서 스테이지 자동 리허설 게이트 결과와 동영상은 제공하지 않는다.

## 다시 빌드하기

Node 22에서 `npm ci`, `npm run build`, `npm run verify`를 실행한다. 만들어진 `before-arrival-showcase.html`은 별도 서버 없이 브라우저에서 열 수 있다. 검증용으로 URL 뒤에 `?state=opening`, `?state=priority`, `?state=saved`를 붙여 각 정지 화면을 열 수 있다.
